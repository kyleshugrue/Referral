# Referral public showcase instructions

## Purpose

This public repository is a deterministic, sanitized portfolio/showcase export. The private `kyleshugrue/Referral_Mainapp` repository is the canonical implementation. Never use the public repository to reconstruct or override private source.

## Privacy gate

- No secrets, credentials, user data, internal URLs, private Worker implementation, sensitive topology, deployment material, source maps, local paths, private comments, or accidental artifacts.
- Treat the allowlist/export process as a security boundary. Review the complete export diff and scan both content and filenames.
- Do not disclose private AI prompts or operational details merely to make documentation look more complete.

## Portfolio truth

- Screenshots must be genuine product screenshots from `referralprofessional.net`; never create synthetic product screenshots.
- Documentation must accurately distinguish implemented behavior, omitted private components, architecture summaries, demo limitations, and planned work.
- Optimize for a hiring reviewer: clear value proposition, truthful architecture, safe setup, verification evidence, tradeoffs, and concise navigation.

## Code review rules

- Audit privacy/security and professional/job readiness independently from the private app score.
- Flag broken links, stale commands, misleading claims, inaccessible media, poor responsive/accessibility behavior, and non-reproducible examples.
- Do not penalize intentionally omitted private code when the public explanation remains truthful and useful.
- For review-only tasks, do not modify files.

## Safety

Never force push, fabricate checks, or weaken export/privacy gates. Publish only after the private source and generated public diff pass their respective verification contracts.
